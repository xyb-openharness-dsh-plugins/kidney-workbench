### 定义

肾癌是起源于肾脏的恶性肿瘤，病理类型以透明细胞癌最常见。「分型 / 分期 / 分级」是三个词：分型说是什么癌，分期说长到哪了，分级说显微镜下的级别——本台三页分开记录，界面不混用。

分型看病理：透明细胞癌、乳头状、嫌色细胞等，命名口径按 WHO / ISUP 分类（本项目出处待核，版本未核实）。分级看显微镜：病理报告常用 WHO / ISUP 1–4 级，另记肉瘤样分化；本台照报告原文，不换算、不合并。分期看 TNM（AJCC 第 8 版口径）：T1a ≤4cm、T1b 4–7cm、T2a 7–10cm、T2b >10cm、T3a 肾静脉或肾周脂肪、T3b 膈下 IVC、T3c 膈上 IVC、T4 侵透筋膜。

常见起点是体检超声 / CT 偶然发现「肾占位」；囊性病变按 Bosniak 分级评估，本台只记原值。遗传与家系方面，VHL 等遗传性肾癌需定期查其他器官，本台只记筛查安排与结果，不推断遗传概率。本台不判断「是不是癌」——那是病理与医生的领域。

### 目前治疗全景概要

下面按期别与线序列出指南里出现过的手段类别。这是「世界上大致有哪些办法」的地图，不是给你排的先后顺序，也不含任何剂量、疗程与适用条件。

- **局限期（T1–T2，可以考虑手术）**：肾部分切除（PN，保留肾单位；解剖或功能性孤立肾、慢性肾病合并肾癌、双肾癌、VHL 等属于其明确适应情形）；根治性肾切除（RN）；消融（RFA / 冷冻，不能手术或特定情形）；主动监测（AS，小肿块、特定情形，本台按影像原文并列大小，不连线、不算 mm/年、不设阈值）。
- **局部晚期 / 晚期**：靶向治疗（TKI 等，具体药物是否在国内获批、是否在医保内需单独核实）；免疫检查点抑制剂（单用或与靶向联合）；靶向 + 免疫联合方案；指南把「参加登记良好的临床试验」列为一项正式选项。
- **术后 / 消融 / 主动监测的随访**：PN / RN 后 T1–2 前 2 年每 6 个月、然后每年；RN 后 T3–4 前 2 年每 3 个月、然后每 6 个月至 5 年、然后每年；消融 / 密切监测 T1a 前 2 年每 3 个月、然后每 6 个月、5 年后每年；IV 期全身治疗前基线、之后每 6–12 周影像评估（均据 CSCO §7 公开摘录）。
- **贯穿全程**：Cr / eGFR 与术前基线并列，孤立肾 / 双侧 / CKD 按原文标记；症状原话与同日血压 / 甲功 / 尿蛋白并置、不并轴；VHL 等遗传性肾癌的其他器官筛查只记安排。

> 以上是文献与指南里列出的手段，按病期与线序排列，不代表任何一项适合你。选哪一个，这一句需要问你的医生。

## 应用开发目的

肾癌患者与照护者手里散着超声/CT 报告、病理报告、化验单、医嘱，复诊前想自己先理一遍，
却常被三件事卡住：**分型 / 分期 / 分级三个词分不清**、**术后或靶向治疗期间的指标看不懂**、
**主动监测的小肿块每次大一毫米都要心慌一次**。本项目把这些材料收进一个本机工作台：
按原文记录、按日期排好、能点回来源，复诊时照着逐条问医生。
工作台只提供信息解释与记录整理（家族三层边界：事实 / 解释 / 判断——
**判断一句不生成**，固定出口是「这一句需要问你的医生」）。

## 适合人群

- **肾癌患者本人**：晚期靶向/免疫治疗中，或术后第一年盯肾功能，或小肿块主动监测（AS）。
- **照护者**：代记、陪诊、帮整理材料（首版照护者无独立身份，见「明确未做」）。
- **不适合**：需要医疗建议、预后判断、方案推荐的人——那些只能问医生。

## 独特价值（与家族其他癌种工作台的差异）

| 差异点 | 做法 | 对照 |
| --- | --- | --- |
| 分型 / 分期 / 分级 | 三个词三个页签，互不合并，界面不许混用 | 多数癌种只做分期 |
| 肾功能轨道 | Cr/eGFR 趋势与术前基线**并列**，孤立肾/双侧/CKD 按原文标记 | 泌尿族里肾癌独有的长期负担 |
| 主动监测（AS） | 影像大小按报告原文并列，**不连线、不算 mm/年、不设阈值** | 一算就等于替医生判断「该手术了」 |
| IMDC 分层 | 只记录医生判定的原文，**产品不打分**，界面写明「IMDC 是预后模型，不是预测工具」 | 预后模型不是预测工具 |
| 副作用管理 | 症状原话 + 同日血压/甲功/尿蛋白**并置不并轴**，CTCAE 语境照抄不叫 grade | 「因为血压高所以停药」一句不生成 |
| 营养 | **不设营养支持页**、不给食谱 | 肾癌无特定饮食处方证据，设页=暗示有处方 |

## 打开演示

**原型（G1 签认的视觉基准，file:// 直接打开）**：

```bash
open prototypes/v0.2/index.html        # macOS
xdg-open prototypes/v0.2/index.html    # Linux
```

**开发版（v0.3.0，真服务 + 本机资料库）**：

```bash
npm run start -- --workspace ~/我的肾癌资料   # 目录必须你明确指定，不猜、不静默创建
# 打开 http://127.0.0.1:4173/ ；不带 --workspace 会提示用法并退出（exit 2）
```

开发版与原型是同一份渲染代码（`public/app.js` 只有五处定点替换：数据从哪来 / 版本 / 启动顺序 /
默认指标重算 / AI 提示词出口），所以原型上跑过的 70 个页签探针在开发版上同样成立。

演示数据唯一来源 `demo/build-demo-data.mjs`（同时产 sqlite 与 `demo-data.js`，重跑字节稳定）：

```bash
npm run demo:data     # 重新生成演示数据（2 档案 / 25 指标 / 95 数据点 / 10 条试验）
npm run check:schema  # schema 冻结合同
npm run check:demo    # 演示数据与 schema 列一致性
npm run probe:proto   # 原型无头走查 70 (页签 × 档案) + 一图秀断言 + 截图
npm run probe:dev     # 开发版无头实测（真服务 + 真数据 + 34 页签账 + 溢出 + 截图 2 张）
npm run test          # 33 项单测（store / api / client / ui-parity）
npm run check         # 家族检查链 9 步（版本/语法/冻结合同/文案红线/列一致/单测/包检查）
npm run audit         # 家族一致性审计（当前 33/33）
```

## 数据与边界（诚实口径）

- **患者数据 100% 模拟**，无真实病例。
- **临床试验是真实登记摘录**：2026-10-24 经 unified-trial-mcp 采集，CDE 363 + CTV 358 共 721 条；
  8 个肾癌关键词宽口径检索，**标题明确含肾癌/RCC 表述的只有 68 条**，其余为宽检索带入的
  生物等效性研究、肾功能/肾病/移植/尿路上皮等非肾癌表述与实体瘤早期试验（登记记录只有
  标题级字段，无法逐条判定适应症，不剔除、如实说明）。演示选的 10 条均在 68 条内。
  登记 ≠ 有效 ≠ 安全 ≠ 可入组；状态一律「登记状态，未核实」。
- **界面药名的获批状态未逐条核实**（DEV-PLAN 已知风险 3），用药以医嘱与说明书为准。
- 提醒只来自用户自己的记录或日期，不来自医学阈值。
